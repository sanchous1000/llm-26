## Описание задания

В работе нужно развернуть три языковые модели из разных семейств с OpenAI-совместимым REST API, подготовить три русскоязычных промпта разных типов (генерация, классификация, извлечение данных) и прогнать каждый промпт на каждой модели в двух режимах: с параметрами сэмплинга по умолчанию (режим A) и с изменёнными гиперпараметрами (режим B). Все прогоны сохраняются, после чего сравнивается длина ответа в токенах, точность и адекватность, стабильность и повторяемость, наличие ошибок и выдуманных фактов, а также время отклика, число токенов ввода и вывода и скорость токенизации и генерации.

## Использованные технологии и модели

Оборудование: ноутбук с NVIDIA GeForce RTX 3070 Laptop (8 ГБ видеопамяти), процессор Intel Core i7-12700H, 32 ГБ оперативной памяти. Система Windows, модели запускались внутри WSL2 (Ubuntu 24.04, Python 3.12.3). Версия драйвера NVIDIA 616.92 (CUDA 13.4).

Модели (все в 4-битной квантизации AWQ):

- Qwen/Qwen2.5-7B-Instruct-AWQ, семейство Qwen, 7B параметров;
- AMead10/Llama-3.2-3B-Instruct-AWQ, семейство Llama, 3B параметров;
- thesven/Phi-3.5-mini-instruct-awq, семейство Phi, 3.8B параметров.

Фреймворки и библиотеки:

- vLLM 0.30.0 (сервер с OpenAI-совместимым API), PyTorch 2.13.0 (сборка под CUDA 13.0);
- в логах сервера: внимание считается через FlashAttention 2, AWQ-слои через ядро Marlin;
- openai (клиент), transformers (замер скорости токенизации), pandas (сводные таблицы).

## Результаты работы

### Промпты

Тексты лежат в `source/prompts.py`.

P1, генерация: письмо клиенту интернет-магазина «ТехноМир» о задержке заказа №48215 на 3 дня, с извинениями, скидкой 5% и новым сроком доставки до 12 октября, объёмом до 120 слов.

P2, классификация: пять обращений нужно отнести к категориям Billing, Tech support или Sales и вернуть только JSON-массив меток. Эталон: Billing, Tech support, Sales, Tech support, Billing.

P3, извлечение: из описания наушников Aurex Pulse нужно получить JSON с ключами название, бренд, цвет, ёмкость_аккумулятора_мАч, вес_г, гарантия_мес. Гарантии в тексте нет, поэтому правильное значение для неё null, по этому полю видно, выдумывает ли модель данные.

### Режимы

Режим A: гиперпараметры в запросе не передавались. Сервер запускался с `--generation-config vllm`, чтобы не подтягивались настройки из файла `generation_config.json` модели (у Qwen там temperature 0.7, top_p 0.8, top_k 20, repetition_penalty 1.05). Действуют значения vLLM по умолчанию: temperature 1.0, top_p 1.0, top_k и штраф за повторы выключены, `max_tokens` не задан, поэтому генерация может идти до конца контекста (4096 токенов).

Режим B: temperature 0.2, top_p 0.9, max_tokens 400 (изменены три параметра).

Каждая комбинация модель, промпт, режим запускалась 3 раза. Кэш префиксов был выключен (`--no-enable-prefix-caching`), чтобы повторные запросы не получали заниженное время до первого токена. Все ответы сохранены в `results/*.json`, сводные таблицы в `results/runs.csv` и `results/summary.csv`.

### Качество ответов

Проверки автоматические (`source/checks.py`), считаются по сохранённым ответам. В P2 отдельно считается формат (плоский массив из пяти меток) и верность меток по смыслу. В P3 отдельно считается, верны ли значения полей, и названы ли ключи так, как в задании.

| Что проверялось | Qwen, A | Qwen, B | Llama, A | Llama, B | Phi, A | Phi, B |
|---|---|---|---|---|---|---|
| P1: письмо только на русском, прогонов из 3 | 1 | 3 | 0 | 1 | 0 | 3 |
| P2: формат, плоский массив меток, прогонов из 3 | 3 | 3 | 0 | 0 | 1 | 0 |
| P2: верных меток из 5 по смыслу (среднее) | 5 | 5 | 1.0 | 3.0 | 4.3 | 4.0 |
| P3: значения верны, из 5 (среднее) | 5 | 5 | 0 | 0 | 5 | 5 |
| P3: ключи названы как в задании, прогонов из 3 | 0 | 0 | 0 | 0 | 0 | 0 |
| P3: выдумана гарантия, прогонов из 3 | 0 | 0 | нет JSON | нет JSON | 0 | 0 |

Что видно в самих ответах:

- Qwen, P1, режим A: в двух письмах из трёх модель посреди ответа переходит на китайский и переписывает письмо целиком по-китайски, в одном из них ещё есть обрывки турецких слов. В режиме B все три письма на русском, в них сохранены номер заказа, скидка и срок доставки, и все письма укладываются в 120 слов.
- Qwen, P3: значения полей правильные во всех прогонах (бренд Aurex, чёрный цвет, 450 мАч, 52 г, гарантия null). Но ключ `гарантия_мес` модель каждый раз пишет с ошибкой (`garantia_мес`, `ГАРАНТИЯ_МЕС`), а в четырёх прогонах из шести вместо `бренд` появляется корейское `브랜드` (три раза) или `брэнд` (один раз). Режим B этого не исправил.
- Llama, P1, режим A: во всех трёх прогонах получается набор слов на разных языках вперемешку с кодом, ответ идёт до границы контекста (3965 токенов, около 41 с). В режиме B письма читаются, но в двух из трёх есть английские слова посреди русских (`sincerное`, `assure`, `logistics`).
- Llama, P2: в режиме A верный формат не получен ни разу (один раз список из 7 меток, два раза бессвязный текст). В режиме B во всех трёх прогонах один и тот же ответ: словарь вида `{"billing": ["1", "4"], ...}` вместо массива меток, по смыслу из пяти обращений верно разнесены три.
- Llama, P3: вместо JSON модель пишет программу на Python для разбора текста, в режиме B все три ответа обрезаны по `max_tokens`. Задание не выполнено ни в одном режиме.
- Phi, P1: тексты на русском, но во всех шести прогонах письмо длиннее заданных 120 слов (в среднем 172 слова в режиме A и 136 в режиме B), в тексте остаются заготовки `[Имя клиента]` и `[Ваше Имя]`. Часть слов не существует в русском языке или употреблена не по смыслу (например, «поблажка», «правомоник-послушник»). В режиме A это заметнее, в подписях встречаются бессмысленные должности («правомоник-послушник», «нартель-специалист»).
- Phi, P2: правильный плоский массив получен один раз из шести (режим A, первый прогон, все пять меток верны). В остальных случаях модель возвращает массив объектов вида `{"category": "Billing"}` и ошибается в третьем обращении (вместо Sales ставит Tech support, один раз Billing), то есть верно четыре метки из пяти. В режиме B во всех трёх прогонах получается один и тот же ответ с тем же форматом и той же ошибкой.
- Phi, P3: значения полей верны во всех шести прогонах, гарантия null. Но ключи модель переводит на английский (`name`, `brand`, `color`, `warranty_months`) вместо заданных русских, а после JSON добавляет пояснение обычным текстом, хотя просили вернуть только JSON.

## Выводы

Гиперпараметры по умолчанию в vLLM оказались плохим выбором для небольших квантованных моделей. При temperature 1.0 без отсечения хвоста распределения Qwen иногда вставляет иноязычные фрагменты, Llama 3B в режиме A выдаёт практически бессвязный текст, а Phi пишет письма заметно длиннее и с большим числом несуществующих слов (532 токена против 398, разброс 167 против 3 токенов). Отсутствие ограничения `max_tokens` усугубляет проблему: бессвязная генерация не останавливается и занимает весь контекст (40 секунд против 2 секунд на нормальный ответ у Llama). Режим B (temperature 0.2, top_p 0.9) у всех трёх моделей убирает самые грубые дефекты и делает длину ответов предсказуемее. Какой из двух параметров даёт основной вклад, по этим данным сказать нельзя, потому что менялись оба сразу. Для этого нужны отдельные прогоны, где меняется только один параметр. Объяснение «слишком случайный выбор токенов» правдоподобно, но отдельно не проверялось.

В режиме B ответы становятся более повторяемыми (у Qwen в P1 два разных ответа из трёх вместо трёх, у Phi и Llama в P2 три одинаковых ответа), но повторяются и ошибки. Phi в P2 при temperature 0.2 три раза подряд выдала один и тот же неверный формат и одну и ту же ошибку в метке, а в режиме A со случайным выбором токенов один из трёх ответов оказался полностью верным. Полной детерминированности при temperature 0.2 нет: у Qwen и Llama на P1 повторы отличались друг от друга.

Следование инструкциям сильнее зависит от модели, чем от настроек. Qwen единственная выдала плоский массив меток с полностью верным результатом (5 из 5 во всех шести прогонах P2). Phi справилась со смыслом, но не с форматом: в P2 вернула массив объектов, в P3 перевела ключи на английский и дописала пояснение. Llama 3B не смогла вернуть требуемый формат ни в P2, ни в P3, и параметры сэмплинга это не исправили. Ни одна модель не назвала ключи в P3 точно так, как в задании.

Выдуманных фактов в проверяемых местах не найдено. Гарантию, которой нет в тексте, ни Qwen, ни Phi не придумали, номер заказа, скидка и срок в письмах переданы верно. У Llama проверить P3 не удалось, так как она не вернула JSON.

Скорость генерации от гиперпараметров не зависит, она определяется моделью: около 63-67 токенов в секунду у Qwen 7B, 97-112 у Llama 3B и 108-116 у Phi 3.8B. Время до первого токена соответственно 0.10-0.12 с, 0.05-0.06 с и 0.06-0.07 с. Скорость токенизации у всех порядка миллиона токенов и выше в секунду (у Phi 1.8 миллиона), но токенизаторы разные, и один и тот же промпт занимает 122, 131 и 139 токенов, поэтому сравнивать длину ответов в токенах между моделями нужно осторожно. Эти цифры получены на коротких промптах и трёх повторах, поэтому годятся для сравнения моделей между собой, но не как точный бенчмарк.


## Инструкция по запуску

Нужны Windows с WSL2 (Ubuntu), видеокарта NVIDIA и драйвер на стороне Windows, поддерживающий CUDA 13 (в WSL драйвер ставить не нужно).

1. В WSL создать окружение и поставить зависимости:

```bash
python3 -m venv ~/venv-vllm
source ~/venv-vllm/bin/activate
pip install vllm==0.30.0
pip install -r source/requirements.txt
```

2. Запустить сервер с первой моделью (одна модель за раз, предыдущий сервер остановить командой Ctrl+C):

```bash
vllm serve Qwen/Qwen2.5-7B-Instruct-AWQ --max-model-len 4096 --gpu-memory-utilization 0.86 --max-num-seqs 16 --max-num-batched-tokens 1024 --generation-config vllm --no-enable-prefix-caching --port 8000
```

Параметры памяти подобраны под 8 ГБ видеопамяти: при свободных 6.95 ГиБ значение `--gpu-memory-utilization` выше 0.869 не запускается. Флаг `--generation-config vllm` нужен, чтобы режим A использовал значения vLLM, а не файл настроек модели.

3. Когда в логе появится `Application startup complete`, можно вручную проверить модель одним запросом (во втором окне WSL, не трогая то, где крутится сервер):

```bash
curl -s http://localhost:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "Qwen/Qwen2.5-7B-Instruct-AWQ",
    "messages": [{"role": "user", "content": "In two sentences, what is a KV cache in LLM inference?"}],
    "temperature": 0.2
  }' | python3 -m json.tool
```

`"model"` должно совпадать с тем именем, которым поднят сервер.

4. В том же окне запустить прогон:

```bash
cd source
python main.py
```

Скрипт сам определяет имя модели с сервера и сохраняет ответы в `results/<модель>.json`.

5. Повторить шаги 2 и 4 для остальных моделей, меняя имя модели в команде запуска сервера:

```bash
vllm serve AMead10/Llama-3.2-3B-Instruct-AWQ --max-model-len 4096 --gpu-memory-utilization 0.86 --max-num-seqs 16 --max-num-batched-tokens 1024 --generation-config vllm --no-enable-prefix-caching --port 8000
```

```bash
vllm serve thesven/Phi-3.5-mini-instruct-awq --max-model-len 4096 --gpu-memory-utilization 0.86 --max-num-seqs 16 --max-num-batched-tokens 1024 --generation-config vllm --no-enable-prefix-caching --port 8000
```

6. Собрать сводные таблицы:

```bash
python analyze.py
```

Появятся `results/runs.csv` (все прогоны) и `results/summary.csv` (средние по модели, промпту и режиму).
