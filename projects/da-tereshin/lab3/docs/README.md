# Материалы агента и датасет

- `tickets.json` — билеты: идентификатор, вопрос, связанные сцены и источники.
- `scenes.json` — карточки сцен: идентификатор, название, происхождение,
  длительность в секундах и описание наблюдаемых событий.
- `evaluation/tasks.json` — задачи для оценщика: реплики пользователя,
  критерии успеха и метаданные. Сейчас одна задача T01 из трёх реплик.

Каждый JSON содержит массив записей. Идентификаторы B01, S01, S02 и T01
связывают записи между файлами. Для новых материалов добавляем записи
в соответствующий массив.

В задачах `input` и `expected_output` заданы для каждой реплики в `turns`.
`history_dependent` отмечает зависимость ответа от истории, `expected_tools`
задаёт обязательные инструменты для реплики. Дополнительные вызовы допустимы;
повторный поиск теории не обязателен, если она доступна в истории.
Критерии пока оцениваются вручную. Для T01 успех означает выполнение
всех критериев всех трёх реплик.

Агент получает билеты и сцены через разрешённые инструменты. Из задач ему
последовательно передаются только тексты `input`. Каталог `evaluation`
содержит эталоны и не должен быть доступен агенту через файловые инструменты,
retrieval или MCP. Само разделение папок не ограничивает доступ: это нужно
учесть при настройке обоих агентов.

Поле `page` и элементы `pages` — номера страниц PDF из метаданных корпуса,
а не печатная пагинация. Тексты теории остаются в корпусе Лабы 2;
здесь хранятся ссылки на них. Обе сцены вымышленные.

Исходное обсуждение сохранено в DIALOG.md. Рабочие данные теперь находятся
в JSON; дальнейшие изменения материалов вносим сюда.
