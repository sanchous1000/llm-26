# Оценочные вопросы и разметка

В наборе 20 вопросов на русском к английской документации Kubernetes Concepts:
10 single-hop (`q01`–`q10`) и 10 multi-hop (`q11`–`q20`). Это одновременно
проверяет межъязыковой поиск. Multi-hop требует объединить правила из разных
документов, например ConfigMap и Deployment, StatefulSet и DNS, LimitRange и HPA.
Single-hop может требовать несколько чанков одного документа.

Вопросы, ответы и свидетельства подготовлены ассистентом по содержимому
локального корпуса, без выбора источников по результатам векторного поиска.
Все 61 цитата проверены по нормализованным документам и текущим чанкам.
Разметка привязана к снимку `release-1.35`, коммит
`8817d358864b70a9710c5ad34f78df6a239be33d`, и чанкам `3cccc393ec5ee49d`
(800 токенов, overlap 100, заголовки только в метаданных).

## Файлы

- [questions.md](questions.md) — вопросы, ответы и источники для чтения.
- [questions.json](questions.json) — исходный набор: вопрос, тип, эталонный
  ответ, шаги объединения фактов, утверждения и точные цитаты с путями и URL.
- [labels/3cccc393ec5ee49d.json](labels/3cccc393ec5ee49d.json) — ID релевантных
  чанков, группы свидетельств, позиции цитат, параметры и хеши входных файлов.
- [labels/3cccc393ec5ee49d.tsv](labels/3cccc393ec5ee49d.tsv) — бинарные qrels
  в формате TREC: `question_id 0 chunk_id 1`, разделитель — табуляция.

## Как читать разметку

Каждое `evidence` в questions.json — отдельное необходимое основание ответа:
`claim` объясняет факт, `quote` содержит подтверждающий фрагмент документа.
В labels.json ему соответствует `evidence_group` со всеми чанками того же
документа, в которых нашлась эта цитата. Пробелы и переводы строк при сопоставлении
не различаются; семантическая похожесть вместо совпадения не используется.
`span_start` и `span_end` задают срез Python `chunk.text[start:end]` в символах
Unicode, конец не включён.

`relevant_chunk_ids` — объединение найденных положительных чанков для вопроса.
Оценка `1` означает, что чанк содержит хотя бы одно выбранное свидетельство;
она не означает, что одного чанка достаточно для полного ответа.
Если одна цитата встречается в нескольких чанках, это альтернативные попадания:
достаточно любого из них. Для полного покрытия вопроса нужно найти хотя бы один
чанк **для каждого** `required_evidence_id`.

Например, для `q16` нужны правило подстановки requests из LimitRange,
определение CPU utilization и формула HPA. Нахождение только формулы ещё
не покрывает вопрос. Покрытие групп нужно проверять отдельно от обычных
Recall@k/MRR по плоскому списку qrels.

Положительные метки проверены по цитатам. Остальные чанки имеют статус
`unjudged`: все возможные дубли и перефразировки в других разделах не размечены
как отрицательные. Если при оценке в top-k попадёт другой корректный источник,
его следует проверить и добавить в разметку. До такой проверки Precision@k
по этим qrels отражает только известные положительные метки.

## Перестроение привязки

Из каталога `projects/ad-shinyakov/lab2`:

```bash
python scripts/annotate_questions.py \
  --chunks data/chunks/3cccc393ec5ee49d
```

Скрипт использует только стандартную библиотеку Python. Модель, эмбеддинги
и Qdrant не нужны. Повторный запуск создаёт те же JSON и TSV.
При новом чанкировании передайте каталог новой версии: вопросы остаются
прежними, а файл меток получает имя новой версии чанков.

Скрипт проверяет уникальность ID, непустые чанки, наличие всех цитат,
совпадение коммита и количество источников. Для multi-hop дополнительно
проверяется наличие минимум двух документов и отсутствие одного чанка,
содержащего все выбранные свидетельства. Если цитата исчезла или пересекла
границу новых чанков, скрипт завершится ошибкой: нужно пересмотреть фрагмент
свидетельства, а не молча исключать его из эталона.

Перед оценкой сравнивайте SHA-256 questions.json, chunks.jsonl и manifest.json
с сохранёнными значениями в labels.json. Для оценки по другому снимку корпуса
нужно заново проверить ответы и источники, затем обновить разметку.
